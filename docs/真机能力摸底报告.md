## 三、关键发现：`?` 树探测失效，能力判定失去校正

这是本次摸底**最严重的问题**，直接影响需求⑤「识别设备支持的协议、指令」。

**现象**：`probe_device_commands()` 在三台设备上均返回 `keywords=0`、`catalog_supported=[]`。

**为什么严重**：项目设计里能力判定优先级是 **`?` 树实测 > 镜像矩阵 > display 探测**。`?` 树是"实测证据"，用来校正矩阵的乐观估计。它一旦失效，判定就只剩矩阵猜测。

**矩阵偏乐观的实锤**：S3700 是**二层交换机**，却被判定支持 `bgp`、`isis`、`mpls`、`mpls_ldp`、`ipsec` 等三层特性。若 `?` 树能工作，这些应被实测证据推翻。

**推论**：需求⑤目前处于"能出结果但结果不可信"的状态。修复 `?` 树抓取应优先于扩充命令目录。

> 补充：设备角色识别中路由器被判为 `unknown`（交换机正常），同一类"解析不够稳"的问题。

## 四、踩到的坑（后续开发必须遵守）

### 1. 必须先注入，再查 RPC
未注入时 `send_ensp_ctrl_cmd("status")` 返回体里 `has_topo` 为 `None`，表现得像"拓扑没加载"，极易误判。**顺序只能是：注入 → 查状态**。

### 2. eNSP 解析 `.topo` 需要约 2 分钟
主视图就绪（`wait_for_main_view`）≠ 拓扑已载入。若在 `devices=0` 时调 `start_all`，RPC 会返回 `devices: 0`，**开机指令打空且不报错**。
→ **必须轮询到 `devices > 0` 再开机**。`open_topology_in_ensp()` 内部已有该等待逻辑，自写流程时不能跳过。

### 3. eNSP 提权运行时，非管理员进程无法注入
`OpenProcess` 返回 `ERROR_ACCESS_DENIED (5)`，表现为"等待主视图超时"。本次即遇到：eNSP 以管理员运行（pid 14280），本机进程非管理员，连 `taskkill /F` 都被拒绝。
→ 已实现自提权（见第五节）。

### 4. 杀掉启动脚本会带走 eNSP
eNSP 作为子进程会被父进程退出波及。已改用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP` 启动。

### 5. eNSP 运行数分钟后会自行退出
多次观察到 eNSP 在空闲数分钟后 pid 消失。**长时间采集任务需要容忍 eNSP 重启并支持断点续采**。

## 六、`?` 树修复结果（真机复测通过）

### 修了三个缺陷

| # | 缺陷 | 表现 | 修法 |
|---|------|------|------|
| 1 | **target 键名不一致** | 路由层传 `console_port`，探测层读 `port` → `int(None)` 抛错被上层吞掉，**静默返回 0 关键字且无任何报错** | 新增 `_normalize_target()`，双向补齐 `port` / `console_port`，并推断 `mode` |
| 2 | **裸 socket 直连，没有唤醒与认证** | 连上后直接发命令，设备还停在登录提示上，首条命令被吞 | 改用已成熟的 `domain.console_connection.ConsoleConnection`（含唤醒 `\x03`、用户名/密码认证、关分屏、提示符识别），并新增 `open_console_session()` |
| 3 | **命令结尾用 `\r\n`** | VRP 控制台只认裸 `\r`，`\r\n` 会让命令被吞、后续全部 "Unrecognized command" | `_console_send()` 改为发 `\r` |
| 4 | **`display version` 被分段截断** | 只回来前三行（138 字符），恰好丢掉带型号的一行 → `device_type` 永远 `unknown`，设备类型过滤形同虚设 | 新增 `read_until_prompt()`（没读到提示符就继续读），并在仍无型号时回退到输出更短的 `display device` |

|---|---|---|

**最有价值的变化**：`device_type` 判出来之后，设备类型过滤才真正生效——
`vlan_create`、`vlanif_ip`、`trunk_port`、`access_port`、`stp`、`eth_trunk`、`vrrp`、
`firewall_*`、`wlan_ac` 这些交换机/防火墙/AC 专属条目，不再被误报为「路由器也支持」。

### 新增回归测试
`tests/test_command_probe_target.py`（11 项）：target 归一化、`console_port` 端到端、
缺失端口报错、`display device` 回退、`read_until_prompt` 读到提示符即停、
**`_console_send` 必须以裸 `\r` 结尾（防 `\r\n` 回归）**、连接必须发唤醒字节。

全量单元测试 **128 项通过**（原 117 + 新增 11）。
